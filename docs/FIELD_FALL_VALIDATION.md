# 현장 낙상 검증 및 카메라 설치 가이드

이 문서는 Hailo 도착 전 Dahua + Raspberry Pi 5 CPU 환경에서 Rule Detector와
Temporal GRU를 비교하는 최소 현장 절차다.

## 1. 무엇을 낙상으로 볼 것인가

낙상은 단순히 사람이 빠르게 눕는 자세가 아니라, 의도하지 않은 균형 상실 또는
급격한 하강 뒤 낮은 자세가 일정 시간 지속되는 사건으로 정의한다.

- 양성: 전방·측방·후방으로 균형을 잃고 바닥/매트에 도달한 연기 낙상
- 음성: 걷기, 의자 앉기, 숙이기, 바닥에 앉기, 천천히 앉았다 눕기
- hard negative: 의도적으로 빠르게 눕기, 신발 끈 묶기, 바닥 물건 줍기

빠르게 눕기는 실제 시스템이 구별하기 어려운 경계 사례다. 시연 낙상 대체 동작으로
쓸 수는 있지만, 실제 낙상이라고 단정하지 않고 별도의 `quick_lie` 음성/경계 항목으로
기록한다. 천천히 앉았다 눕는 동작을 낙상으로 보지 않는 현재 목표는 타당하다.

## 2. Dahua 권장 설치

- 높이 2.0~2.4 m, 아래쪽으로 15~30도 기울인다.
- 이동/낙상 방향과 정면 일치보다는 30~45도 대각 시야가 유리하다.
- 머리, 엉덩이, 무릎, 발목과 바닥 도달 지점이 프레임 안에 계속 보여야 한다.
- 시연 구역은 화면 중앙에 두고 사람 높이가 프레임 높이의 대략 35~70%가 되게 한다.
- 책상·의자 때문에 엉덩이/무릎/발목이 가려지는 구도와 강한 창문 역광을 피한다.
- 완전 천장 수직 시야는 현재 측면형 학습 데이터/규칙과 차이가 크므로 피한다.
- 구도와 초점/줌을 고정한 뒤 ADL와 낙상 데이터를 같은 구도에서 수집한다.

## 3. Rule과 GRU 비교가 뜻하는 것

두 검출기에 같은 동작을 보여주고 아래 네 값을 각각 기록한다.

| 지표 | 계산/의미 |
|---|---|
| TP | 연기 낙상에서 경보가 발생 |
| FP | ADL인데 경보가 발생(오탐) |
| FN | 연기 낙상인데 경보 없음(미탐) |
| 지연 | 바닥 도달 시각부터 경보 확정 시각까지 |

Rule은 가장 큰 사람 1명의 현재 기하와 상태 전이를 사용한다. GRU는 사람별 track의
20-frame 시퀀스를 분류한다. 따라서 여러 사람이 있으면 서로 다른 사람을 보고 있을 수
있으며, Rule 상태와 GRU 최신 클래스가 같을 필요가 없다.

GRU의 `falling`/`fallen`은 가장 높은 확률의 클래스다. 이것만으로 경보가 아니다.
`falling + fallen >= threshold`가 설정된 연속 횟수만큼 유지되어
`shadow_alert=true`가 될 때만 GRU Shadow 경보로 센다. Shadow 결과는 아직 MQTT로
전송하지 않는다.

## 4. 시험 절차

1. 휴대전화 시각을 NTP 동기화하고 시험자/동작/방향/반복 번호를 정한다.
2. ADL 30분을 먼저 수행한다. 경보가 한 번이라도 나면 시각과 동작을 기록한다.
3. 안전 매트와 보조 인원을 두고 전·측·후방 연기 낙상을 각각 5회 수행한다.
4. 각 반복에서 동작 시작과 바닥 도달 UTC 시각을 기록한다.
5. 빠르게 눕기와 천천히 앉았다 눕기를 각각 별도 음성 항목으로 5회 넣는다.
6. 시험 후 Shadow 로그와 Pi4 이벤트 DB를 대조한다.

기록 표 예시:

| trial_id | 실제 라벨 | 방향/동작 | 시작 UTC | 바닥 도달 UTC | Rule 경보 시각 | GRU Shadow 시각 | 비고 |
|---|---|---|---|---|---|---|---|
| F-SIDE-01 | fall | 측방 낙상 | | | | | |
| N-QLIE-01 | non-fall | 빠르게 눕기 | | | | | | hard negative |

요약 명령:

```bash
cd /home/pi/Home-Safety-System
PYTHONPATH=src .venv/bin/python scripts/summarize_shadow_log.py --json
```

스키마 1.1부터 Shadow JSONL은 같은 시점의 `rule`과 사람별 `tracks`를 함께 저장한다.
영상/얼굴 이미지는 저장하지 않는다. Rule 실제 경보는 Pi4 PostgreSQL에도 저장된다.

## 5. 선택 기준

- ADL 오탐이 0에 가까운 것을 우선한다.
- 전·측·후방 낙상의 event recall을 따로 본다.
- 평균뿐 아니라 가장 느린 지연과 track 분절도 확인한다.
- 현장 검증 전에는 GRU를 Shadow로 유지하고 Rule만 MQTT active로 둔다.
- GRU가 Rule보다 오탐을 줄이면서 필요한 낙상을 놓치지 않을 때만 active 승격한다.

문제가 특정 동작/구도에 집중되면 임계값만 낮추지 말고 해당 현장 영상을 동의하에
hard-negative/validation 데이터로 추가해 Mac에서 재학습·평가한다.
