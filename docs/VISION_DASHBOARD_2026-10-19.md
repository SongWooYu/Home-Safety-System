# 비전 테스트 화면·한글·카메라 화각 개선

적용일: 2026-10-19. Pi5 `http://192.168.1.20:8080`의 개발·시연 화면.

후속 수정: 같은 날 야간에 실제 AI 루프의 옛 shadow 정리 코드가 운영 EdgeFall
track을 지우는 버그를 수정했다. 아래 UI 분류만으로는 해결되지 않았던 문제다.
이제 영상 아래에 동작 후보/모델 미동의/모델·동작 동의와 수치 기록 상태를 표시한다.
판정 정책도 v5로 바뀌었으므로 [후속 보고서](EDGEFALL_TUNING_2026-10-19.md)를 참고한다.

## 한글 이름이 네모로 나온 원인

기존 코드는 비ASCII 문자열을 OpenCV FreeType으로 그렸으나 기본 글꼴이
`DroidSansFallbackFull.ttf`였다. 이 장비의 해당 글꼴에는 완성형 한글 글리프가
없었다. 글꼴을 읽는 데 성공했으므로 예외 처리도 실행되지 않고 네모가 그려졌다.
따라서 단순히 UTF-8 인코딩을 바꾸거나 등록 데이터를 다시 만드는 것으로는
해결되지 않는다.

`fonts-nanum`을 설치하고 `NanumGothic.ttf`를 명시했다. 글자는 채운 형태로
렌더링하고 어두운 라벨 배경을 넣어 밝은 영상에서도 읽을 수 있게 했다.
기존 한글 이름과 `미등록`을 그대로 사용할 수 있다. 얼굴 DB 변경은 없다.

```sh
sudo apt-get install -y fonts-nanum
```

설정: `config/cameras.yaml`의 `face_recognition.label_font`.
폰트가 없는 장비에서는 기존 ASCII `KNOWN`/`UNKNOWN` 폴백을 사용한다.
회귀 테스트는 서로 다른 한글 `홍`, `김`이 서로 다른 픽셀로 그려지는지 검사한다.

## Camera Module 3가 확대되어 보인 이유와 조치

출력 프레임 크기와 센서 읽기 모드는 별개다. 작은 RGB 출력을 요청하면 Picamera2가
중앙을 잘라 읽는 작은 센서 모드를 선택할 수 있다. `ScalerCrop`만 크게 지정해도
해당 모드 자체가 잘라낸 영역 밖은 복원할 수 없다.

현재는 센서 모드 목록에서 다음 기준으로 고른다.

1. 목표 해상도와 15 FPS 지원
2. 원본 센서를 가장 넓게 읽는 `crop_limits`
3. 같은 화각이면 가장 작은 센서 출력 선택
4. `ScalerCropMaximum` 적용

이 장비에서 확인한 실제 설정:

- 센서 읽기: 2304×1296, 2×2 binning
- 센서 영역: `(0, 0, 4608, 2592)` — 전체 영역
- 처리·얼굴 입력: 960×540
- `raw=None`, `buffer_count=4`, `queue=False`
- 실제 캡처: 약 15 FPS

출력 영상을 단순히 줄이거나 늘린 것이 아니라 잘려 있던 화각을 확보했다.
상태 API의 `camera_view`에서 선택된 모드·센서 영역을 확인할 수 있다.
렌즈가 보지 못하는 영역까지 넓히는 광학 줌아웃은 불가능하다. 더 넓은 장면이
필요하면 카메라 위치를 뒤로 옮기거나 Wide 모델을 사용해야 한다.
전체 화각에서는 얼굴이 작아지므로 등록할 때 얼굴 전체가 충분한 크기로 보이는
거리를 유지해야 한다.

근거: [Picamera2 공식 센서 모드 설명](https://github.com/raspberrypi/picamera2/discussions/756),
[Camera Module 3 공식 사양](https://www.raspberrypi.com/products/camera-module-3/).

## 새 대시보드

파일을 `templates/index.html`, `static/dashboard.css`, `static/dashboard.js`로 나눴다.
폐기된 Rule/GRU의 숨겨진 화면과 갱신 JavaScript도 제거했다.

- 밝은 중성 배경, Dahua 주 화면과 얼굴 인식·등록 보조 화면
- 상단에 큰 실시간 낙상 판정
- 확정: 빨간 상단 경보 + 영상 위 큰 한글 `낙상 감지`
- 의심: 노란 경보, 확정과 구분
- 회복: 회복 관측 중으로 표시
- 현재 상태가 금방 해제돼도 마지막 확정 기록은 사용자가 확인할 때까지 표시
- `기록 확인`은 이 브라우저의 표시 확인이며 MQTT 경보를 취소하지 않음
- Pi4 브로커 연결 여부를 별도로 표시; 설정이 켜졌다는 이유로 전송 성공이라고 쓰지 않음
- 상태를 4초 이상 받지 못하면 연결 경고를 표시하고 마지막 판정을 현재 판정으로 쓰지 않음
- 확대는 기존 `<img>`의 레이아웃을 바꾸므로 추가 MJPEG 연결을 만들지 않음
- 화면 숨김 시 스트림 해제, 복귀·잠자기 해제·네트워크 복귀 시 최신 연결 재생성
- 두 카메라 영상의 중복 이름/FPS 헤더와 사람이 없을 때의 영어 하단 바 제거

영상의 박스·관절·이름은 계속 Pi5에서 렌더링한다. 새 경보는 좌표 변환이 필요 없는
HTML 표지이며, 얼굴 안내는 작은 SVG/CSS 그림이다. 영상에 Canvas 추론/그리기를
추가하지 않았다. 외부 CDN이나 브라우저 AI 모델도 필요 없다.

## EdgeFall 준비 상태와 점수의 의미

기존 `edgefall_state=warming`, `edgefall_probability=0`는 사람 없음·관절 부족을
구분하지 못했다. 기존 API 필드는 호환성을 위해 두고 `analysis` 표시 정보를 추가했다.

| 표시 | 의미 | 움직임 점수 |
|---|---|---|
| 사람을 기다리는 중 | 보이는 추적 대상 없음, 카메라는 실행 중 | `—` |
| 관절 확인 필요 | 사람 후보는 있지만 추적/어깨·골반이 유효하지 않음 | `—` |
| 초기 움직임 관측 | 유효한 사람의 초기 관측 48프레임 미만 | 초기 점수 |
| 움직임 분석 중 | 유효한 사람을 계속 관측 중 | 현재 모델 점수 |
| 연결 끊김 / 분석 오류 | 현재 분석 결과를 사용할 수 없음 | `—` |

점수는 약 3.1초의 관절 변화에서 얻는 temporal MLP 출력이다. 실제 낙상 발생
확률의 교정된 추정치가 아니며, 최종 경보도 아니다. 최종 경보는 기존 EdgeFall의
하강·자세·시간 조건까지 함께 사용한다. 예를 들어 점수가 높아도 `fall_state`가
normal이면 빨간 경보를 표시하지 않는다.

중요한 구현 차이: upstream 시간 분류기는 첫 관측부터 계산하고, 아직 없는 과거
구간에는 초기 관측을 사용한다. `초기 움직임 관측`은 이 초기 점수를 해석하도록
돕는 화면 설명이다. 모델에 새 48프레임 강제 대기 조건을 추가하지 않았다.
이번 작업은 모델 가중치, 낙상 임계값, MQTT 이벤트 계약을 변경하지 않는다.

## 얼굴 방향 안내

`자동 다각도 등록`을 누르면 약 10초 동안 SVG 얼굴과 화살표가 다음 순서로 바뀐다.

1. 정면
2. 화면 오른쪽 화살표 방향으로 고개를 20~30° 돌림
3. 화면 왼쪽 화살표 방향으로 돌림
4. 정면으로 복귀

진행 막대는 안내 촬영 시간이며, 얼굴 특징이 실제로 승인된 비율이 아니다.
촬영 뒤 서버가 선명도와 방향별 특징을 검증하며 성공한 경우에만 채택 장수를 표시한다.
실패하면 서버가 알려준 원인을 표시한다. 실제 3D 스캔·깊이 센서·위변조 검사가
추가된 것은 아니다. 등록은 키 없이, 목록·삭제는 기존 관리 세션으로 보호한다.
