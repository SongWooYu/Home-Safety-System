# v6: 학습 모델 골반 입력 단위 오류 수정

## 사용자 시험과 결론

사용자가 60Hz 설정 후 Dahua 플리커 소실을 확인했다. 그러나 반복 연기 낙상은
v5에서 의심만 발생하고 확정되지 않았다. 약 21:38:15–21:41:32의 관절 기록에서도
확정 0건, API 이벤트 의심 32건을 확인했다. 장치가 느려 분석을 안 한 것이 아니다.

핵심 원인은 **학습 모델에 잘못된 단위의 골반 Y 좌표를 넣은 로컬 연결 오류**다.
앞서 작성했던 “시간 모델도 0~1 정규화 hip Y를 기대한다”는 설명을 정정한다.
전체 모델 정확도 문제와 입력 계약 오류를 구분하지 못한 상태에서 규칙 우회 경로로
확정을 늘렸고, 이를 막은 v5에서 미탐이 두드러졌다.

### 원인 확정 및 사용자 현장 확인 (2026-10-19)

v6 배포 후 사용자가 “이제 잘 되는 것 같고 판단이 잘 된다”고 확인했다.
이번 **반복 연기 낙상이 의심에 머물던 회귀의 확인된 핵심 원인**은
사전학습 MLP의 골반 Y 입력 단위 불일치다. 근거는 다음 세 가지다.

1. 고정 가중치의 평균값과 upstream feature 경로가 픽셀 입력을 사용한다.
2. 동일한 관절 기록에서 입력 단위만 수정했을 때, 사용자가 확인한 빠른 연기
   낙상이 미검출에서 확정으로 바뀐다. 임계값·후보 대기시간은 그대로다.
3. 실제 v6 운영 배포 후 사용자 시험에서도 판정 개선이 확인됐다.

따라서 이번 수정은 민감도 상향이나 재학습이 아니라 **연결 코드 오류 수정**으로
기록한다. v6를 현재 운영 기준으로 유지한다. 다만 사용자 확인은 정성적 현장
검증이며, 모든 방향·환경의 낙상 정확도나 천천히 눕기 오탐률까지 확정한 것은
아니다. 과거 모든 미탐·오탐을 이 오류 하나로 설명하지 않는다.

## 증거: frozen 가중치의 정규화 평균

Hailo 모델의 `temporal_model_weights_hailo.h`는 56개 frame feature를 사용한다.
0-based index 51이 골반 Y이며, sequence feature의 시간 bin 6개 평균은 다음과 같다.

```text
300.90787, 304.41489, 308.09180, 311.56802, 314.82025, 318.95639
```

이 값은 640 픽셀 공간의 Y다. 예를 들어 화면 중간 골반은 다음 두 소비자에 서로
다르게 들어가야 한다.

| 소비자 | 기대 입력 | 화면 중간 예 |
|---|---|---:|
| 기하 상태기계 | 영상 높이에 대한 0~1 비율 | 0.5 |
| frozen Hailo temporal MLP의 hip-Y feature | 640 공간 픽셀 | 320 |

v5까지는 둘 다 0.5를 받았다. MLP의 여러 평균·변화량·분산 feature가 학습 분포와
달라져 점수와 양성 발생 시점이 잘못됐다. 단순히 임계값을 낮춰 해결할 문제가 아니다.

v6는 `observationFrom()`의 정규화 좌표는 유지하고, `temporalFrameFrom()`에서
**모델용 observation 복사본의 hip_y만 640배**로 복원한다. 실제 keypoint 좌표나
사람 박스, MLP 가중치, 임계값, geometry 조건은 변경하지 않는다.

## 같은 기록을 이용한 오프라인 비교

관절 기록 10,398프레임 중 사람 검출 프레임은 2,378개다. 영상을 다시 촬영하지 않고
같은 pose/monotonic timestamp를 각 라이브러리에 넣었다. Hailo 재추론, MQTT 발행,
운영 서비스 재시작 없이 비교했다.

| 실험 | 모델 hip Y | 후보 대기시간 | 확정 이벤트 수 |
|---|---|---:|---:|
| 기존 v5 재생 | 잘못된 0~1 | 1.5초 | 0 |
| 시간만 연장 | 잘못된 0~1 | 4초 | 2 |
| 입력 단위만 수정 | 학습 단위인 픽셀 | 1.5초 | 7 |
| 단위 수정 + 시간 연장 | 픽셀 | 4초 | 7 |

따라서 **운영에는 단위 수정만 적용**한다. 후보 대기시간은 1.5초로 유지한다.
처음에는 3초 뒤 모델 양성/1.5초 후보 만료가 보였으나, 단위 수정 후 해당 지연도
줄었다. 시간 조건 확대를 필수 해결책으로 단정할 근거가 없어 적용하지 않았다.

수정 후 확정 시각(KST): 21:40:04.218, 21:40:14.614, 21:40:27.989,
21:40:48.840, 21:40:57.374, 21:41:07.667, 21:41:19.486.
모두 `temporal_positive=true`이며 모델/기하 동시 조건을 충족했다.

사용자가 21:40:14 전후를 **빠르게 넘어지는 연기**라고 확인했다. 이 구간은
21:40:13.917 하강 후보 → 21:40:14.614 확정, 후보부터 약 0.70초다.
실제 낙상 시작 시점을 영상으로 정밀 라벨링한 end-to-end 지연은 아니다.

중요: 7건은 재생 결과이지 “실제 낙상 7건 정답”이나 재현율이 아니다. 나머지 동작의
정답 시각은 없고, 천천히 눕기 오탐률도 아직 계산할 수 없다. 앞부분의 관절 누락과
추적 분할은 별도로 남아 있다. Hailo frontend의 letterbox/postprocess 차이와
현장 카메라 구도 일반화도 이 수정으로 검증됐다고 주장하지 않는다.

## 회귀 검증과 변경하지 않은 것

- frozen 모델 평균이 pixel scale인지 컴파일 시 검증.
- 실제 tracker가 geometry에는 0~1, model feature 51에는 pixel을 사용하는지 검증.
- tracker 모델 출력과 독립적인 동일 feature 분류기 출력의 일치 검증.
- 즉시 충격/시간차 충격/수평 지속의 세 경로 모두 모델 음성이면 확정 불가 검증.
- 모델 양성만으로 정지 자세를 낙상 확정하지 않는 조건 유지.
- synthetic fixture 일부는 올바른 단위에서 모델 양성으로 바뀌므로, 정책 테스트는
  모델 음성/양성을 직접 주입해 검증하고 실제 MLP 통합 테스트와 분리했다.

75%/3회 연속, 입력/AI/화면 FPS, 60Hz 카메라 설정, 얼굴 등록 DB, Pi4, MQTT 계약은
변경하지 않았다. 대시보드 영상 아래에 `v6 · 입력 단위 수정`을 표시한다.
