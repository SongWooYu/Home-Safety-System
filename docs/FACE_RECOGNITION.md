# 얼굴 등록과 인식

## 현재 방식

- 얼굴 검출: OpenCV YuNet
- 얼굴 정렬·특징 추출: OpenCV SFace
- 입력 카메라: Camera Module 3 또는 ABKO 웹캠
- 분석 주기: 카메라당 약 0.5 FPS
- 유사도: 정규화 특징 벡터의 cosine similarity
- 기본 등록 판단 임계값: 0.45
- 최소 얼굴 크기: 약 70 px
- 저장 파일: `data/faces.json` (Git 제외)
- 원본 얼굴 사진: 저장하지 않음

YuNet이 얼굴과 눈·코·입 랜드마크를 찾고 SFace가 얼굴을 정렬한 뒤 특징 벡터로
바꾼다. 등록자는 여러 템플릿을 가질 수 있고, 인식 시 모든 템플릿과 비교하여
가장 높은 점수를 사용한다. 등록 여부는 기본값이 아니며 최고 유사도가 0.45 이상일
때만 등록자로 판정한다. 등록자는 영상 박스와 Pi5/Pi4 카메라 카드에 등록 이름으로,
그 외에는 `미등록`으로 표시한다.

## 다각도 등록 절차

대시보드 `http://192.168.1.20:8080`에서 다음 순서로 등록한다.

1. Camera Module 3 또는 웹캠을 고른다.
2. 이름을 입력하고 `정면`을 등록한다. 등록에는 관리 코드가 필요하지 않다.
3. 고개를 약 20~30도 왼쪽으로 돌리고 같은 이름으로 `왼쪽`을 등록한다.
4. 고개를 약 20~30도 오른쪽으로 돌리고 같은 이름으로 `오른쪽`을 등록한다.
5. 확인이나 삭제가 필요할 때만 `등록자 목록·삭제`를 열고 관리 코드를 입력한다.
6. 목록에 이름 옆으로 정면·왼쪽·오른쪽이 모두 표시되는지 확인한다.

각 방향 등록은 약 1초 동안 5프레임을 가져오며 한 명의 얼굴이 명확한 프레임
3개 이상이어야 성공한다. 같은 이름과 같은 방향을 다시 등록하면 그 방향만
교체되고 다른 방향은 보존된다. 기존 단일 벡터 형식은 최초 로드 때
`legacy` 템플릿으로 호환되며 다음 저장 때 버전 2 형식이 된다.

## 촬영 품질 기준

- 얼굴이 영상 높이의 약 20% 이상 되게 가까이 선다.
- 얼굴에 역광이나 강한 그림자가 생기지 않게 한다.
- 한 번에 한 사람만 화면에 둔다.
- 좌우 등록 때 완전한 옆얼굴이 아니라 양쪽 눈 또는 한쪽 눈과 코 윤곽이 충분히
  보이는 20~30도 각도를 사용한다.
- 안경을 항상 착용한다면 착용 상태로, 자주 바뀐다면 실제 전시 상태와 같은
  모습으로 등록한다.
- 카메라가 다르면 색과 렌즈 특성이 달라질 수 있다. 인식이 불안정하면 같은
  이름의 한 방향을 다른 카메라에서 다시 찍는 것보다 전시에서 주로 사용할
  카메라로 세 방향을 일관되게 등록한다.

## API

등록은 전시 현장에서 바로 사용할 수 있도록 관리 코드 없이 허용한다. 등록자
목록 조회와 삭제는 `X-Face-Admin-Token` 헤더가 필요하다.

- `POST /api/faces/admin/session`: 관리 키를 검증하고 30일 HttpOnly 세션 생성
- `GET /api/faces`: 이름, ID, 등록 방향 조회 — 관리 코드 또는 검증된 세션 필요
- `POST /api/faces/enroll`: 얼굴 등록 — 관리 코드 불필요
- `DELETE /api/faces/<id>`: 한 사람의 모든 템플릿 삭제 — 관리 코드 필요

등록 요청 예:

```json
{"camera_id":"cam3","name":"홍길동","view":"left"}
```

일반 `/api/status`와 MQTT 최신 상태에는 등록 이름, 등록 여부, 유사도와 미등록
얼굴 수를 보낸다. 원본 얼굴 이미지와 embedding은 보내지 않는다. Pi4 DB에는
카메라별 최신 상태만 upsert되지만 등록 이름도 개인정보로 취급한다.

## 보안과 개인정보

특징 벡터도 생체정보이므로 사진이 아니라고 해서 공개 데이터가 되는 것은 아니다.

- `.env`, `data/faces.json`, `runtime/`은 Git에서 제외한다.
- 목록·삭제용 관리 키는 JavaScript 저장소에 보관하지 않는다. 한 번 검증하면
  값 자체가 아닌 서명된 HttpOnly/SameSite 세션만 30일 유지한다.
- 등록 API는 인증 없이 열려 있으므로 8080 포트를 전시장 사설 LAN 외부에 공개하지 않는다.
- 삭제 버튼은 해당 사람의 모든 방향 템플릿을 삭제한다.
- 백업이 필요하다면 암호화된 저장소에 `faces.json`만 별도 보관한다.

## 한계와 다음 개선

현재는 얼굴과 가장 가까운 사람 추적 ID를 장시간 결합하지 않는다. 여러 사람이
겹치거나 얼굴이 너무 작고 가려지면 등록 여부가 잘못 연결될 수 있다. 먼저
다각도 템플릿으로 시연 품질을 확인하고, 필요할 때만 다음을 추가한다.

1. ByteTrack 등 사람 추적 ID와 얼굴 결과의 공간·시간 결합
2. 카메라별 임계값 검증과 unknown 구간 설정
3. 품질 점수(흐림, 밝기, 얼굴 각도) 기반 등록 프레임 선택
4. 전시 동의 절차, 자동 만료, 데이터 삭제 UI
5. Hailo 도착 후 지원 모델로 검출·특징 추출 가속

임계값을 낮추면 등록자를 더 잘 찾는 대신 다른 사람을 등록자로 오인할 위험이
커진다. 실제 참여자 데이터로 false accept와 false reject를 함께 확인한 뒤
조정해야 한다.
